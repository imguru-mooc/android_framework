B-2.5. SSH 공개키/개인키 페어 생성·등록 ★전원 필수 (PuTTY·WinSCP 공용)

비밀번호 로그인 대신 키 인증을 표준으로 합니다. 아래 5단계를 Day 0에 완료하고, Day 1 오리엔테이션에서 전원 확인합니다.

단계 수행 위치 내용
① 키 생성 Windows — PuTTYgen Type: Ed25519(권장) 또는 RSA 3072+ → Generate(마우스 이동) → Key passphrase 설정(필수) → Save private key → 내문서\ssh\aosp_stuNN.ppk
② 공개키 복사 PuTTYgen 상단 "Public key for pasting into OpenSSH authorized_keys file" 박스의 한 줄 전체(ssh-ed25519 AAAA... comment) 복사 — Save public key 버튼의 파일 형식은 사용하지 않음
③ 서버 등록 PuTTY(최초 1회는 비밀번호 로그인) mkdir -p ~/.ssh && chmod 700 ~/.ssh → echo '복사한 공개키 한 줄' >> ~/.ssh/authorized_keys → chmod 600 ~/.ssh/authorized_keys
④ 클라이언트 지정 PuTTY: Connection→SSH→Auth→Private key file = .ppk / WinSCP: 고급→SSH→인증→개인키 파일 = .ppk (또는 Pageant에 .ppk 로드 시 두 프로그램 모두 자동 인증)
⑤ 검증 PuTTY·WinSCP 각각 재접속 시 비밀번호 없이(passphrase만) 로그인되는지 확인. 실패 시: authorized_keys 한 줄 여부/개행 깨짐, ~/.ssh 700·파일 600 권한, 키 파일 경로 재확인

💡 개인키(.ppk)는 절대 서버에 업로드하거나 공유하지 않습니다. 분실 시 서버의 authorized_keys에서 해당 공개키 삭제 후 재발급.

B-3. WinSCP 설정 (수강생 전원, Day 0 완료)

항목 값
프로토콜 SFTP(기본) 또는 SCP — 같은 SSH 계정(22포트), 사이트 저장명 AOSP-BUILD
인증 ★ 고급 → SSH → 인증 → 개인키 파일(.ppk) 지정 (B-2.5 ④). Pageant 사용 시 자동. 비밀번호 없이 접속되는지 확인
북마크 등록 ★ ~/aosp/vendor/edu/ (실습 코드), ~/aosp/frameworks/base/core/java/android/os/custom/ (실습 6-x), ~/aosp/out/target/product/emulator_car64_x86_64/ (산출물), ~/aosp/out/.../system/apex/ (APEX)
편집기 연동 ★ 옵션 → 편집기에서 로컬 편집기(VS Code/메모장++) 연결 — 서버 파일을 더블클릭으로 열고 저장하면 자동 업로드. vim이 익숙하지 않은 주니어의 기본 편집 방식
용도 ① 배포 스켈레톤 코드 업로드 ② 소스 편집(자동 업로드) ③ 빌드 산출물/트레이스(trace.pb)/로그 다운로드 ④ 과제 제출물 회수

B-4. 표준 워크플로: 서버 빌드 → WinSCP 전송 → 로컬 에뮬레이터 검증 (Day 2~4 공통)

[Windows 11 PC]                                   [빌드 서버]
① 소스 편집: WinSCP 편집기 연동 ───(SCP 업로드)──▶  ~/aosp/... 반영
② 빌드: PuTTY(tmux)에서 m / mm  ────────────────▶  out/target/product/... 산출물 생성

  2. 빌드 시간: Day 2 오후 m framework-minus-apex services가 머신별 20분~1시간+ 편차 → "코드 먼저, 빌드는 백그라운드" 원칙 + Day 3 아침 검증 세션으로 흡수.

  4. SELinux: setenforce 0은 개발 환경 전용임을 매 실습마다 고지하고, 정식 정책 작성은 심화 과정으로 연결.
  5. 빌드 서버 동시 부하: 전원이 14:40에 동시 빌드 시 서버 과부하 가능 → -j 값을 1인당 코어 수로 제한(예: -j8)하거나 2개 조로 5분 시차 시작. ccache 공유 설정으로 재빌드 단축.
  6. PuTTY 세션 끊김: keepalive 설정에도 네트워크 단절 가능 → 모든 빌드는 tmux 필수 규칙화. 끊긴 수강생은 tmux attach -t build로 즉시 복귀하는 절차를 Day 1에 리허설.
  7. 파일 전송 실수: WinSCP로 잘못된 경로 업로드/덮어쓰기 방지 — 실습 코드는 반드시 북마크 경로에서만 편집, 원본 백업(.orig) 습관화. 서버 홈 용량 쿼터 모니터링(out 디렉토리 비대화).
  8. 빌드-이미지 버전 불일치: 서버 AOSP 산출 jar을 로컬 AVD에 push할 때 이미지 빌드 차이로 부팅 루프 가능 → 로컬 AVD를 API 36 최신으로 통일, .orig 복원 절차 리허설, 최악 시 이미지 세트 전체 교체(강사 가이드) 준비.
  9. SSH 키 관리: 개인키(.ppk) 유출·분실 대응 절차(공개키 폐기·재발급)를 Day 0 안내문에 포함. passphrase 미설정 금지, Pageant 사용 시 이석 시 잠금.
